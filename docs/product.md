# BeaconHop — 工作导航与窗口首版

日期：2026-10-28。状态：已进入双端实现；实际验证进度见 validation.md，尚无端到端性能验收结果。

## 产品定义

帮助用户快速抵达要做事的地方，并能回到刚才的现场。

显示面积、可见范围与人的注意力都有限，工作却分散在不同容器中。产品需要缩短“想到下一件事”到“已经可以操作目标”的距离。

用三个概念表达未来范围：

| 概念 | 含义 | 首版实例 | 未来可能的实例 |
| --- | --- | --- | --- |
| 目的地 | 可以准确抵达并开始操作的对象 | 某一个具体窗口 | 浏览器标签页、文件段落、编辑器位置、远程会话、Agent 会话 |
| 位置与范围 | 目的地所在的位置，以及本次要查找的边界 | 显示器、虚拟桌面 | 设备、远程环境、空间界面 |
| 工作现场 | 围绕一件事的一组目的地及继续工作的状态 | 首版不提供现场保存或恢复 | 某项目的编辑器、终端、资料页与上次工作位置 |

显示器和虚拟桌面首先是位置与范围；未来可以拥有自己的导航入口。工作现场也不能仅等同于“一组窗口”。这套抽象不要求首版实现通用插件系统、云同步或现场恢复引擎。

## 已确定的首版方向

- 独立桌面应用，macOS 与 Windows 均在首版产品范围内。
- 替代日常窗口切换入口，按具体窗口展示；同一应用的多个窗口不能合并成一项。
- 缩略图概览配合 hint；输入完整 hint 立即切换，也支持鼠标点选。
- 保留按住修饰键、Tab 循环、松开切换的习惯。
- 按住模式中输入 `\` 进入常驻搜索，此后可以松开修饰键。
- 另设直接进入搜索的快捷键。Windows 的 Win + `、macOS 的 Cmd + ` 作为初始默认绑定，均可配置；系统兼容性需要实机验证。
- 两个平台都能设置是否跨虚拟桌面；显示器范围与桌面范围独立。
- 速度和可靠性属于产品交付要求，不能以“已有竞品”作为取消立项的理由。

## 窗口首版边界

| 能力 | 首版范围 |
| --- | --- |
| 找到窗口 | 当前登录用户的普通可交互顶层窗口；覆盖同应用多窗口、最小化、全屏及应用隐藏状态；默认包含最小化和隐藏窗口，可在设置中关闭 |
| 辨认窗口 | 缩略图、应用图标、窗口标题、hint；同标题时用位置等补充信息区分 |
| 搜索窗口 | 按窗口标题、应用名过滤；支持中文输入及输入法组合态；无需安装浏览器插件 |
| 准确抵达 | 激活选中的具体窗口；最小化窗口恢复；跨桌面时抵达窗口现有位置，保留其原有布局 |
| 最近往返 | 按最近使用顺序循环，快捷往返最近两个窗口；完整导航历史浏览器不在首版 |
| 范围设置 | 当前/全部显示器 × 当前/全部虚拟桌面；概览、hint 与搜索共用同一候选范围 |
| 基础设置 | 两类唤起快捷键、显示器和桌面范围、必要权限状态与诊断入口 |

窗口能力不足时，应准确展示限制。例如拿不到缩略图时仍可通过标题、图标辨认；无法取得焦点的系统特殊窗口不能显示为“切换成功”。锁屏、登录界面与安全桌面不属于普通窗口首版。

浏览器标签页、应用内文档列表、文件内容搜索、窗口排列、关闭/批量管理窗口、工作现场保存恢复、跨设备控制、AI 调度、通用启动器和剪贴板均不纳入首版。浏览器和远程桌面应用自身的顶层窗口仍可正常参与切换。

## 交互规则

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| 未唤起 | 按住修饰键并按切换键 | 显示概览，进入按住模式 |
| 按住模式 | Tab / Shift + Tab | 按最近使用顺序向前 / 向后选择 |
| 按住模式 | 松开修饰键，且没有未完成的 hint | 切到当前选中窗口 |
| 按住模式 | 输入完整 hint | 立即提交并切到对应窗口，无需等待松键 |
| 按住模式 | 输入 `\` | 转入常驻搜索；之后松开修饰键不提交 |
| 未唤起 | 按直接搜索快捷键 | 进入常驻搜索 |
| 常驻搜索 | 输入文本、方向键选择、Enter | 过滤并确认目标；输入法组合态的 Enter 先交给输入法 |
| 任一面板状态 | 点击窗口卡片 | 切到该窗口 |
| 任一面板状态 | Esc | 取消并恢复原焦点 |

已实现的细节规则：

- hint 使用没有前缀歧义的编码；完整编码才提交，避免短码同时又是长码前缀。
- hint 输入后目标立即生效，但仍要正确处理后续修饰键释放，避免目标应用收到多余字符或意外快捷键。
- 已输入部分 hint 时松键，取消本次选择，避免误跳到高亮窗口；这与普通 Tab 循环的松键提交分开处理。
- 一次按住会话中，hint 和卡片位置保持稳定；缩略图异步更新。目标关闭就失效，不把旧 hint 重新分配给另一窗口。
- 搜索模式中的普通字符均用于文本搜索；搜索结果使用方向键、Enter 或鼠标确认，不与 hint 抢字符。
- 原窗口已关闭时，取消应结束面板并保留系统可用焦点，不强行恢复失效句柄。

## 桌面与显示器的精确定义

“当前显示器”以唤起时前台窗口所在显示器为准，无前台窗口时 macOS 取鼠标所在显示器，Windows 取系统返回的最近显示器。

macOS 使用每显示器独立 Spaces 时，“当前桌面 + 全部显示器”表示所选显示器各自当前活动 Space 的并集，不能只用主显示器的 Space 过滤。Windows 按系统虚拟桌面语义执行。两端提供一致的设置含义，平台内部实现可以不同。

范围在唤起时确定。桌面范围与显示器范围取交集；某窗口出现在多个位置时仍只列一次。切换目标时先解决所在桌面和窗口状态，再把键盘焦点交到准确窗口；跨桌面不等于移动窗口到当前桌面。

## 首版验收与性能目标

验收以“目标窗口可以接收用户输入”为完成点，不能以发出激活调用、应用进程变前台或面板消失替代。

建议的性能预算，均未实测，也不是已经承诺的结果：

- 常驻后，快捷键事件到面板可交互：P95 不高于 50 ms。
- hint / 搜索输入到可见反馈：P95 不高于 16 ms；枚举与截图不能阻塞逐键输入。
- 记录首次启动、窗口数量及缓存状态；分别报告 20 / 50 / 200 窗口场景，不只测空桌面。
- 从确认选择到目标获得焦点的端到端耗时单独记录，同桌面与跨桌面分开报告，包含系统动画的实际等待。
- 同时记录后台 CPU、内存与截图频率，避免用持续高负载换取唤起速度。

两端至少验证：同应用多窗口及同标题窗口；最小化、隐藏、全屏；单屏与多屏；四种桌面/显示器范围组合；窗口创建和关闭；输入法组合态；快速反复唤起与取消；权限拒绝和恢复；目标关闭或无法激活。

关键通过条件：hint 不误指向；模式转换不误提交；搜索与概览候选一致；切换后面板不抢回焦点；没有按键泄漏；失败有准确反馈。运行时验证记录必须注明操作系统版本与硬件环境。

## 实现与交付

已经采用 Tauri 2、React 和 Rust 共享交互状态机与设置界面。macOS 使用 Swift / Accessibility / ScreenCaptureKit，Windows 使用 Win32 / DWM；窗口能力保留在原生适配层。完整交互不依赖 uTools。

原生权限、准确焦点、虚拟桌面兼容性、打包与性能分别验收。当前证据与剩余限制记录在 [validation.md](validation.md)，不把源码编译或浏览器测试等同于双端实机验收。

## 相关依据

- [Windows LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)：键盘钩子可阻止按键继续传播，因此不能笼统断言 Windows 无法替换 Alt + Tab；具体兼容性仍需实机验证。
- [Windows RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)：Windows 键组合存在系统保留约束，不能将 Win + ` 当作未经验证的必定可用默认值。
- [Windows IVirtualDesktopManager](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ivirtualdesktopmanager)：公开接口覆盖窗口桌面归属等能力，不等于完整桌面切换能力；切换路径需单独验证。
- [Apple screensHaveSeparateSpaces](https://developer.apple.com/documentation/appkit/nsscreen/screenshaveseparatespaces)：macOS 存在各显示器使用独立 Spaces 的配置。
- [AltTab Spaces 实现](https://github.com/lwouis/alt-tab-macos/blob/master/src/switcher/state/Spaces.swift)：可作为 macOS 桌面归属处理的实现研究入口，不代表本项目已验证该方案。
