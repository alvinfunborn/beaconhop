# 四层导航

2026-10-30，开发版源码能力；不是已安装版本的验收记录。

BeaconHop 统一桌面、窗口、应用窗口和窗口内内容。Screen Buoy 负责目标桌面或窗口内的鼠标操作。各应用只通过适配器提供目标枚举与准确激活，不实现自己的切换面板。

## 入口与后续操作

| 层级 | 按住切换 | 直接搜索 | 候选范围 |
| --- | --- | --- | --- |
| 全部窗口 | Win + Tab | Win + 反引号 | 设置允许的窗口 |
| 应用窗口 | Alt + Tab | Alt + 反引号 | 唤起时聚焦应用的窗口，继续遵守桌面/显示器范围 |
| Tab 与会话 | Ctrl + Tab | Ctrl + 反引号 | 聚焦原生窗口内，由适配器提供的目标；Codex 有下述例外 |
| 桌面 | Ctrl + Win + Tab | Ctrl + Win + 反引号 | 系统提供的桌面，包含空桌面及 macOS 全屏 Space |

Win 在 macOS 上对应 Command，配置值写作 `Super`。Tab 循环、Shift 反向、松开全部唤起修饰键提交；完整 hint 立即提交。多修饰键组合（如 Ctrl + Win + Tab）只松开其中一个键时仍保持选择模式，避免按键映射临时释放 Ctrl 时提前提交高亮项。按反引号也可从按住模式进入常驻搜索。所有快捷键可改，Ctrl + Tab 在没有可用适配器的应用中原样放行。

桌面层首次按 Ctrl + Win + Tab 时，优先选最近离开的桌面，快速松键即可在最近两个桌面间往返。历史按本次进程内系统确认的桌面变化更新，也包含系统快捷键或 Mission Control 的切换；失败请求不会更新历史。没有可用历史时选编号顺序的下一个桌面。缩略图位置与 hint 不按历史重排；继续按 Tab 或 Shift + Tab 按总览顺序移动，直接反向唤起选当前桌面的上一个。

macOS 若使用 Karabiner 等按键映射工具，应检查组合键是否在到达 BeaconHop 前被改写。例如将 Edge 的 `Control + Tab` 映射到其他按键、并设置 `optional: ["any"]`，也会吞掉 `Control + Command + Tab`。需移除或收窄冲突规则；程序合成按键不会经过相同的物理键盘映射，不能代替这项检查。

用 hint 选中目标后，继续按住最后一个 hint 键，再按后续键。BH 和 SB 均在后续键按下时开始接续；BH 下一层为常驻 hint 模式，无需等待旧键松开。旧 hint、后续键和仍按住的唤起键，其重复及松开事件不会操作新层；旧修饰键也不参与新输入的快捷键匹配，可直接按新的 hint。原键松开再按即可重新使用。目标激活仍须确认，Tab 列表异步加载。Tab/方向键选择、Enter 提交、反引号搜索、Esc 取消。新窗口抢占焦点会结束 BH 的非激活面板，避免继续截取别的窗口的输入。

| 后续键默认值 | 动作 |
| --- | --- |
| Win / Super | 窗口层；从桌面进入时只列选定桌面的窗口 |
| Alt | 当前聚焦应用的窗口层；从桌面进入时同样限制在该桌面 |
| Ctrl / Control | 刚选中窗口的 Tab 层；要求对应适配器可用 |
| HintLeftKey 或 HintRightKey | Screen Buoy：桌面层进入桌面级；窗口、应用窗口、Tab 层进入目标窗口级；需单独启用 SB 集成 |

后续键、SB 触发键及左右邻键映射可设置。同一动作可添加多个备选键，按其中任意一个即可，不需要同时按下。清空窗口、应用窗口或 Tab 的后续键仅关闭对应接续入口，不影响全局快捷键。按住 hint 期间，若目标后续修饰键本来已按下，先松开该修饰键，再按一次。普通松键、搜索确认、鼠标点选不会自动接续。失败激活、无关新输入、Esc、配置更改或新导航会话会取消待执行的后续操作。

空桌面可以抵达，并继续进入空窗口列表或桌面级 SB；没有聚焦窗口时，应用窗口层为空。桌面级 SB 无需聚焦窗口：macOS 共享 Spaces 时覆盖所有参与的显示器，各显示器使用独立 Spaces 时仅覆盖所选 Space 所在显示器；Windows 覆盖该虚拟桌面的所有显示器。网格覆盖桌面，控件缓存只接受当前可见窗口及选定显示范围内的点；切离目标桌面或显示器范围改变时结束该 SB 会话。窗口、应用窗口和 Tab 层均保持窗口级范围；Tab 使用其原生父窗口。

## Win + Tab 多显示器空间总览

每屏展示属于该屏的全部窗口，包括隐藏、最小化和其他桌面的窗口。同一显示器上的预览使用相同缩放比例，保留原窗口的宽高和相对大小，标题栏另计。窗口多时共同缩小；选中、搜索不改变展开位置。

布局参考原窗口位置，同时比较贴边、接触边和空余矩形的填空方案，再沿横纵方向收缝。桌面按系统原生顺序保持整组窗口的左右重心关系；单张卡片可以跨过引导区域补空位，不保留固定列、容器或象限。稀疏桌面可以上下排列。淡色渐变与桌面名称表示大致归属。全屏 Space 保留原生顺序，空的当前桌面保留标记，空的其他桌面略过，未知归属单独放在末尾。

展开布局优先让所有窗口完整可见，因此不保证每个窗口原来的上下左右关系。顶部堆叠图标切换到原始坐标与遮挡关系，悬停或选中时也显示原位置轮廓。Hint 居中；紫色方形表示选中，青色圆形表示出发窗口，两者重合时使用紫色加青色环，搜索时仍保留状态符号。界面不再重复显示“层级／选中／出发”等文字。

各屏搜索框同步输入与中文组字。首次正向 Tab 优先最近使用的另一个窗口；后续按展开后的缩略图从左到右、从上到下循环，Shift+Tab 反向。方向键依照最终卡片位置导航。Hint 全局唯一，原有分配保持稳定。窗口增减或下次唤起会重算布局；显示器拓扑变化时取消当前总览，下一次使用新屏幕集合。

当前构建的测试和原生验收见 [validation.md](validation.md)。

## 适配器与能力边界

安装及协议见 [plugins/README.md](../plugins/README.md)，第三方开发入口见 [SDK 文档](../plugins/sdk/README.md)。插件按实际注册和连接动态展示，启停即时生效；适配器重连不会重置停用状态。

| 适配器 | 当前实现 | 限制 |
| --- | --- | --- |
| 浏览器 | Chromium MV3 扩展 + BeaconHop Native Messaging host；枚举聚焦浏览器窗口、激活 tab ID 并回读确认 | 初始目标 Chrome / Edge；每个 profile 单独连接。Safari / Firefox 未实现；无痕模式遵守扩展权限 |
| VS Code | UI extension host 中枚举 `tabGroups`；跨编辑器组准确激活并确认 | 支持文本、diff、notebook；terminal、webview、自定义 editor 未接入 |
| Codex | macOS 内置适配器通过本机 app-server 的 `thread/list` 读取最近 100 个未归档会话，使用官方会话链接打开 | 是持久化会话列表，不是当前 GUI 窗口的已打开 tab 列表。无法读取 GUI 当前会话或确认实际切换，所以禁止自动接后续层；尚无 GUI 端到端验收 |

Codex 默认使用 app-server 默认数据目录；多账户或自定义目录应在设置中填写对应 `CODEX_HOME` 的绝对路径。此设置只控制读取目录；深链接仍由已运行的 Codex app 处理，须与其数据目录一致。只读取会话元数据（标题/首条摘要、工作目录），不读取完整对话、不恢复线程、不发送 turn。当前内置适配器仅检测 macOS 应用。

微信、飞书、其他 terminal 以后各自实现适配器。它们不需要修改按键状态机，也不承诺依靠同一套 Accessibility 树就能稳定列出全部内容。

## 状态与身份

原生窗口身份保留既有规则；插件目标使用 `(provider, instance, context, item)`，不能以标题、URL 或文件名代替身份。同标题的不同 tab 仍是不同目标。插件重启更换 instance；移动、关闭或失效的目标报错，不猜测替代项。

先在原应用仍聚焦时异步枚举，再让搜索面板取得焦点。Ctrl + Tab 快速松键会等待本次枚举结果；若用户随后开始输入或切到其他窗口，取消延迟提交。过期回调不能唤回面板。两处插件同时自称聚焦时拒绝选择，不按标题推测哪个对应原生窗口。

浏览器和 VS Code 激活都要求插件确认确切 context/item，再确认原生父窗口仍聚焦，才能接续 SB。Codex 的链接返回只证明系统接受了打开请求。窗口内内容使用统一展示模型：浏览器默认缩略图网格，Codex 和 VS Code 默认文本列表。插件 context 可声明 text 或 thumbnails；旧插件有缩略图能力时默认网格，否则默认文本。文本列表显示标题、路径/分组及可选摘要，不显示暂无预览，也不请求图片；浏览器缺失缓存时保留占位卡片，用户仍可将网格切为列表。所有展示共用 hint、搜索、选择、激活和基于位置的方向导航，长列表滚动并保持选中项可见。桌面网格展示窗口总览，按显示器与窗口位置拼接缩略图，不包含壁纸。隐藏、最小化与已排除应用的窗口不参与总览；空桌面仍有卡片。关闭缩略图或截图权限不可用时保留窗口位置和名称。长列表滚动，选择项保持可见。窗口层和应用层共用既有稳定 hint；桌面和各插件 context 分别维护 hint，插件 hint 当前只在本次 BeaconHop 进程内保存。

macOS 关闭“显示器具有单独的空间”时，一个桌面总览包含共享该 Space 的所有显示器，按实际屏幕位置排列；开启时，总览只包含该 Space 所属的显示器。桌面激活仍保留具体显示器作为定位依据，预览范围通过独立的 `displayIds` 表达。

## 平台与迁移

macOS 桌面枚举使用现有 SkyLight Space 身份；激活通过 Mission Control 的 Accessibility 控件，并回读当前 Space。控件同时从 WindowManager 的直接显示器节点和 Dock 的 `mc` 子树查找；本机 macOS 27.0.1 使用前者，Dock 的空 `mc` 占位节点不能代表调度中心已打开。该接口随系统版本变化，失败会显示错误。Windows 使用项目既有 `winvd` 版本适配器，仍受 Windows 11 24H2 目标版本限制。切换桌面不创建、删除或移动窗口。

缺少新导航字段的旧设置会迁移：旧默认 Alt + Tab 转为 Super + Tab，Alt + Tab 留给应用窗口。其他旧自定义全局快捷键保留，若与新增默认层冲突，就关闭对应新增层。旧的单键后续配置迁移成数组；旧版 SB 的默认右邻键会补上左邻键，但若左邻键已被另一动作占用则保留原值。自定义 SB 按键和空配置保留；新格式中显式设置的仅右邻键也保留。配置校验拒绝不同动作争用同一个实际触发键，同一动作内别名与固定键指向同一物理键则允许。
